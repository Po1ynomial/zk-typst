# References and graph

## Syntax

A Zettel reference is a native Typst reference with a ten-digit label:

```typst
This follows from @2603231410.
```

The reference does not resolve the target file. It resolves only the target metadata. Resolution is therefore depth one and does not scale with the archive.

## Namespace

Version one reserves every label matching this pattern for Zettel references:

```text
^[0-9]{10}$
```

Consequences:

- `@2603231410` is always a directed Zettel reference.
- Other references remain ordinary Typst labels or bibliography citations.
- Bibliography keys and local labels may not use exactly ten decimal digits.
- A future ID format requires an archive migration.

## Graph edges

Only literal ten-digit reference nodes in Zettel source define links.

The logical graph contains at most one directed link for each ordered source-target pair. A link groups every authored occurrence:

```text
Link
  source: existing Zettel ID
  target: referenced ID
  resolution: resolved or missing
  spans: one source range per authored occurrence
```

Repeated `@ID` references from the same source do not create parallel logical links, but none of their ranges are discarded. LSP consumers can expand the spans for references and diagnostics. Visualizers can use the grouped link directly.

A missing target remains a link with `resolution: missing`; it does not create a synthetic Zettel node. Incoming and outgoing indexes, and any flat occurrence arena used for compact storage, are derived implementation details.

The following do not create links:

- references generated by functions or loops;
- labels assembled from strings;
- references produced by imported code;
- ID-looking text inside raw blocks, strings, or comments.

A literal reference counts wherever it appears in the Zettel AST, including the abstract and metadata markup. Every occurrence contributes an exact half-open UTF-8 byte range to its grouped link. The containing node identifies the source path and source generation.

Byte ranges are the provider's sole stored position representation. This keeps the graph deterministic and independent of consumer position encodings without evaluating Typst.

## Link context

The reason for a connection is handled by writing discipline, not the format. The surrounding prose provides the link context.

## Backlinks

Backlinks are computed from authored connections. They do not manufacture new ones.

For an edge `A -> B`, the backlink shown at B means only "A refers to B". It does not imply `B -> A`, and it is not written back into B.

Backlinks support:

- revising thoughts whose dependencies changed;
- finding the contexts where an idea was later used;
- navigating back from a detailed note to a structure note;
- protecting integrity before removal or migration.

A Zettel with no incoming or outgoing references is valid and produces no diagnostic. Isolated notes are normal while an archive is young or a thought is still being connected.

## Navigation and display

Forward navigation needs no graph lookup:

```text
@2603231410 -> zettel/2603231410.typ
```

The editor conceals the `@ID` and displays the target title. The raw ID remains in the buffer for saving, parsing, LSP processing, and version control.

## Removal

`zk remove <ID>` refuses to delete a Zettel while incoming references exist and prints their locations. Version one offers no automatic unlink operation.
